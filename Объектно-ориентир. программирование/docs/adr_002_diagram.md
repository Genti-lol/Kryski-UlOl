# ADR-002: Выбор отношений между классами на UML-диаграмме

## Контекст
При проектировании диаграммы классов нужно было определить типы связей
между сущностями игры.

## Решение
- `Game *-- GameField` — композиция: поле не существует без игры.
- `Game o-- Player` — агрегация: игрок управляется игрой, но может существовать отдельно.
- `Game --> UI` — ассоциация: игра использует UI, но UI может быть передан извне.
- `GameField *-- Hole` — композиция: лунки не существуют без поля.
- `Hole --> Rat` — ассоциация: лунка может породить крысу (0..1).
- `Player --> Rat` — ассоциация: игрок может ударить 0..* крыс.
- `UI ..> Game` — зависимость: UI отображает состояние игры.

## Рассмотренные альтернативы
1. **Всё через композицию.** Жёсткая связь, сложно тестировать.
2. **Всё через ассоциацию.** Нет чёткого владения, утечки памяти.
3. **Смешанный подход (выбрано).** Композиция там, где есть владение,
   ассоциация — где взаимодействие.

## Последствия
- Чёткое разделение владения и взаимодействия.
- Тестируемость за счёт слабых связей.
- Требует понимания разницы между композицией и агрегацией.
