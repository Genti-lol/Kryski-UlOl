# ADR-001: Инъекция зависимостей через конструктор

## Контекст
Процедурный код смешивал игровую логику и ввод/вывод. Это затрудняло тестирование:
тесты требовали ручного ввода данных.

## Решение
Выделен класс `UI`, отвечающий за ввод/вывод. `Game` получает `UI`
через конструктор (инъекция зависимостей).

## Рассмотренные альтернативы
1. **Глобальный UI-модуль.** Проще, но сложнее тестировать.
2. **Наследование от UI.** Приводит к жёсткой связи.
3. **Инъекция через конструктор (выбрано).** Гибко, тестируемо.

## Последствия
- Логика тестируется через Mock без реального ввода.
- Легко заменить консольный UI на 3D-графику.
- +1 уровень косвенности.
- Требуется явно передавать UI в конструктор.
